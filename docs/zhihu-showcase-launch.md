# 我让本地 Coding Agent 做了个小游戏，然后让浏览器当裁判

我已经不太相信“AI 会调用工具”这种演示了。

模型能写出一段 HTML，不等于用户真的能点开、开始游戏、得到结果。很多 Coding Agent 的完成标准停在“文件写进去了”，而实际产品的问题往往刚从这里开始。

所以我给 MA + Agora 出了一道很小、但不能糊弄的题：做一个不依赖外部资源的反应速度小游戏。点击 `Start` 后随机等待，面板变绿后点击，必须显示毫秒结果和 `Play Again`。

这次我关心的不是它说了什么，而是下面这条链路是否完整：

1. **真实工具调用**：MA 实际调用 `fs__write_file` 写出单文件游戏。
2. **真实生成物**：生成的 `index.html` 已经公开，不是剪辑出来的界面。
3. **真实浏览器验收**：Playwright 打开生成页面，点击 `Start`，等待页面进入 `go` 状态，点击面板，再确认出现毫秒结果和 `Play Again`。

提示词、生成物、终端录制、浏览器 GIF 和验收脚本都在这里：

https://github.com/zimoos/ma-showcase/tree/main/demos/02-reaction-time

主项目：

https://github.com/zimoos/my-agent

这不是性能跑分。第一次本地生成这个小游戏时，模型大约两分钟后才进入文件工具；我把这个限制也保留在记录里，而不是剪掉。对我来说，真正值得讨论的是：一个本地 Agent 能否把任务推进到可观察、可验证的结果，而不是它在终端里看起来有多忙。

MA 现在是 MIT 开源，支持 LM Studio、DeepSeek 和 Agora。本地模型、工具调用、长任务上下文和浏览器验证都应该留下证据，而不是只留下“完成了”的一句话。

如果你手上有能让 Agent 露馅的真实任务，欢迎直接带着提示词、预期产物、运行环境和失败现象来挑战它。我们更需要失败证据，而不是又一个看起来很顺的 Demo。
