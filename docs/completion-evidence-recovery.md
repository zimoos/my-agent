# Completion evidence during development

An attempted command is not automatically a permanent user requirement. A negative search result is a completed observation. A failed validation remains a requirement until a newer run proves the same validation scope; its original failure stays in the tool transcript.

The action audit recognizes a bounded literal shell subset. Validation identity includes the working directory, actual runner, test targets, selection flags, environment and output destinations. A leading `cd ... &&`, built-in Node test reporters, runner deadlines and output-only observers can change without changing the validation target. The successful replacement must run directly in the foreground, return exit code zero and verified action evidence, and account for process cleanup. Shell pipelines and printed `PIPESTATUS` do not prove a validator passed.

The audit offers two bounded repair opportunities before a final response. An unrelated passing test cannot satisfy another failed target. A later failure reinstates its obligation. Unknown process scope remains unresolved even after a new identical command succeeds: a new process cannot prove that an older one stopped.

Unknown external scripts, mutations mixed into test recipes, input redirections, substitutions and unrecognized shell syntax retain the exact-action requirement. The audit never discards an unknown write merely because a different test passed, and does not instruct the model to repeat an external mutation blindly. Existing alias, command and directory evidence protections remain in force.

The September 2026 application records contain both safely reconcilable test wrappers and opaque recipes mixing log deletion, scripts and tests. This change does not retroactively certify those runs or reinterpret missing provider/browser evidence as success. Local process tests exercise an actual failing Node test hidden by `tail`, a repair, a direct passing run, and the final task event. Their provider sequence is scripted; real-model independent delivery still requires a fresh acceptance run.
