# MA Runtime Module

## Ownership and current scope

- Feature development A owns production files and this module document. Independent Q owns tests and fixtures; feature development must not edit them.
- Batch A1 defines only the six exported data contracts in `contracts.ts`; those types do not validate or authorize values. Batch A2 adds only the standalone execution journal and its structural/association validation.
- `execution-journal.ts` owns a private per-session `execution.jsonl` and `.writer.lock`. Its writer assigns contiguous sequence numbers, accepts at most 256 unfinished appends including the active sync, and synchronizes accepted records before resolving them. A write/sync failure prevents further writes by that instance.
- Complete invalid records are corruption; an unconfirmed final segment is reported separately and prevents opening a writer. Never truncate, skip corrupt complete lines, or clear a crashed writer's lock. `readExecutionJournal` is diagnostic only and does not acquire write authority or repair data.
- A2 does not implement identity issuance, tool/Cloud authorization, Turn gating, Pi history restoration, or owner-death lock recovery. A recorded receipt remains caller-supplied data, not independently verified external evidence.
- R2a adds only ModelCallBinding, ModelCallReceipt, InvocationOrigin and TurnCompletion types, plus model.prepared/model.dispatching/model.receipt/execution.model-bound/turn.completed journal shapes. Required fields must be own enumerable data properties; optional fields are read only when own and valid. Model scope matches the enclosing event, and model receipt callId matches its call. The six earlier event shapes remain readable without rewriting records or inventing an origin.
- requestSha256 means SHA-256 of the UTF-8 bytes of native JSON.stringify applied to the final actual supplier request, without sorting or canonical reordering. R2a validates only the lowercase 64-character hex shape; the later bridge owns request construction and hash computation. AbortSignal, raw requests and responses do not enter these journal records.
- R2a journal acceptance alone does not enforce cross-event model/tool state. R2b below adds the shared TurnGate transitions; retry decisions, recovery and authorization still belong to later integration. A turn.completed record alone is not Mission acceptance or proof of financial settlement.
- A3 adds `turn-gate.ts` for a fresh journal in one process. Its async factory reads the journal before exposing the gate. Existing records or an incomplete tail require recovery; read/write failure pauses the gate. Neither path silently resumes an old Turn.
- One journal object has one gate owner: calls for the same session share initialization and the same gate instance; a conflicting session is rejected with `TURN_INVALID_SCOPE`. Ownership is registered before journal reading, so concurrent factory calls share cancellation state. A newly opened journal object still follows the existing-record recovery requirement.
- `stop` fences the target Turn synchronously, including a pending registration or dispatch fsync. Dispatch attempts already entering the journal remain in-flight even if cancellation prevents returning a permit. A permit proves durable local intent only, not tool authorization, a Cloud budget grant, or remote execution.
- A3 binds subsequent Turns to the first operationId and budgetRef. R2b releases this local binding only after durable normal completion, so a trusted Host may explicitly register another operation/budget with a larger epoch. Stop preserves the original binding; neither path grants or resets Cloud budget authority. Old call/tool identities and receipts retain their original scope permanently within the gate.
- R2b adds prepareModel/markModelDispatching/recordModelReceipt/bindInvocation/recordReceipt/complete to the same shared gate, journal and queue. Every input, including factory options, requires its declared own enumerable data fields; optional fields are copied only when own and valid. Model attempts and tool origins are reserved synchronously; receipts occupy their identity before queueing, and confirmed state changes only after journal synchronization.
- Prepared models may close only with not_sent. Once dispatching starts, not_sent requires evidenceRef; an unknown model/tool receipt can become confirmed only with evidenceRef, and conflicting terminal receipts are rejected. Evidence references remain caller-provided correlation data: the later bridge must establish their truth. Same active-Turn model calls may run concurrently; explicit unknown or unresolved revoked/older-Turn dispatch blocks new model dispatch. A pending unknown receipt remains blocking until a confirmed receipt is durable.
- A new tool dispatch requires a durable binding to a succeeded model receipt and the immutable full Invocation. The tuple (sessionId, epoch, callId, toolCallId) cannot be rebound to another executionId. Confirmed diagnostic failures terminate the tool obligation; stopConfirmed alone cannot clear unknown risk. Late receipts update only their original stored identity and never issue new work.
- complete claims the Turn synchronously only when no prepared model, pending/unconfirmed dispatch or bound tool without a terminal receipt remains. It synchronizes turn.completed before returning a local completion receipt; stop and complete cannot both win. Journal failure pauses the gate, old nonempty logs remain diagnostic recovery_required, and no origin is synthesized for old events. This is not Mission acceptance, Cloud settlement, automatic recovery or a provider/tool permission.
- F1 adds an internal text-only `pi-session.ts` using the real pinned Pi SDK, an explicit borrowed ModelRuntime, empty resources and an in-memory Pi session. Built-in/custom tools, automatic resources, retry, cache warming, compaction and telemetry are disabled. It neither loads the old loop nor grants Host/Cloud authority.
- F1 captures each Turn independently, rejects reused Turn IDs/non-increasing epochs, and holds the prompt slot through SDK preflight and final idle. It does not bind a facade permanently to one operation/budget. Durable authorization and normal Turn completion remain separate later work.
- User cancellation is latched before awaiting SDK abort. A public agent_start listener repeats the abort after preflight creates the SDK run; close waits for the entire prompt and idle before disposal. Late observations retain their original run, observers receive independent snapshots, and unexpected tools fail separately from user cancellation. Local idle/cancel does not prove remote effects stopped or financial settlement.
- The initial isolated batches above remain the history of the foundation contracts. The current complete-module first pass permits A to connect all MA runtime, provider, tools/resources, recovery and CLI/ACP production paths. Other owners' files and all test/fixture files remain out of scope.

## Complete-module product implementation

- `my-agent/host` exports the MA protocol v2 types, `openMaSession`, `createMaAcpAgent` and `runMaAcpServer`. Host owns bootstrap identity, per-Turn scope, permission decisions, quote references and actual budget authority. ACP prompt metadata cannot supply that authority; the trusted `resolveTurn` callback resolves it.
- Fresh `openMaSession` connects the one Pi loop to the existing `ProviderRuntime` through the public Pi OpenAI codec and the model bridge. The bridge disables underlying retries, captures each original Turn and logical call, writes a new `call_` identity for each actual attempt, and correlates tool origins to the completed response. It does not infer success from a local stream ending without a finish reason.
- Trusted bootstrap nativeRequestAuthority defaults to host; Cloud uses host authority even if its transport runtime exposes a native preparation method. Explicit runtime authority makes the trusted ACP HostControl wrapper freeze each actual native supplier request using the same injected ProviderRuntime before external Host preparation and provide supplierRequestSha256; the wrapper must verify Host echoes the exact 64-character lowercase hash. The model bridge does not freeze a second time. Never infer authority from URLs or provider names. The manifest freezes authority for that session; old manifests mean host and cannot resume as runtime. Standalone CLI retains Host-owned native preparation without a second bridge preparation. Every failed/rejected/cancelled attempt discards its prepared bytes in finally. Cloud proxy JSON is not a substitute for the supplier hash; control headers and AbortSignal remain in memory only.
- The OpenAI 4.x native body override uses an explicit DataView over the frozen bytes' exact offset and length. Passing a pooled Buffer directly would widen the SDK request to its entire backing buffer; neither unrelated memory nor additional bytes may enter the approved supplier request.
- The controlled tool adapter binds the immutable full source and original model call before one execution. Receipts persist before Pi receives the result; unknown outcomes fence the Turn. Ordinary confirmed diagnostic failures remain terminal tool receipts. Only the safe result projection enters Pi history; private MCP metadata stays on the trusted local channel.
- Resource loading uses an explicit public `ResourceLoader` snapshot assembled from approved files, skills and MA-owned event handlers. It does not construct `DefaultResourceLoader`, scan default extension folders, enable Pi built-in tools, or treat a project's executable extension as approved.
- The optional virtual UI binding comes only from Host and names the actual server, instance and three current/act/search tools. Its frame is a request-context slot, not a second transcript. Historical results retain audit text/images; only a matching confirmed frame grants current action handles. Cancellation, compaction and unknown results invalidate that frame.
- The three-tool virtual UI restriction applies to the bound server's zimoos.* namespace. Other tools explicitly supplied by that same trusted server remain in its catalogue and still require original model-call correlation and Host permission; adding virtual UI must not remove image-generation or collaboration tools.
- Root bootstrap, CLI chat/run/TUI and standalone ACP now delegate to openMaSession/createMaAcpAgent. The old loop is no longer a production bootstrap route; arbitrary package subpath exports are removed. The remaining legacy Agent shape is a UI compatibility adapter, not a model/tool loop.
- HTTP MCP uses the official SDK with HTTPS or explicit loopback HTTP only, no redirects and no replay. Both transports preserve pagination, outputSchema/annotations and trusted invocation metadata; requestTimeoutMs is a trusted integer 1000–3600000, progress never extends that deadline, and cancellation is only a request. Child processes receive the approved environment plus a small runtime allowlist, not all Host credentials.
- Memory controls expose the existing Agora controller through the same facade and preserve uncertain mutations. Manual compaction, automatic compaction and branch summaries use the same captured model bridge, Turn and cancellation scope. Agora's internal memory is never part of the Pi engine.
- Memory verification records contain only strict schema-v1 verification facts; `pending.report` is always null on disk. Provider report/error text remains in memory and is never part of recovery evidence. Resume opens without following links or blocking on FIFOs, verifies the same file descriptor is a regular 0600 file, and rejects unknown versions, extra/missing fields, malformed pending facts and mismatched session/profile before exposing memory control. Invalid old records are not silently rewritten or accepted; they require explicit inspection rather than blind replay.
- Pi compaction and branch-summary reserves are bounded by the frozen model context/output capacity, and recent-context retention fits the selected context window. The pinned SDK's explicit already-compacted/session-too-small manual outcomes complete without a model call and emit a visible unchanged notice. They never emit a fake context.compacted event; every other failure stays a failure.
- Explicit recovery holds the session writer lock, restores original durable receipts, queries original Host call/execution identities and only appends a missing original tool result. It never repeats tools or uses a new quote to clear unknown effects. Dead-writer reclamation requires a matching Host/session and proven absent PID; ambiguous or recovery-guard ownership remains blocked.
- Before the first provider dispatch, a fresh Pi history is materialized from the SDK's public header and existing entries only, synced, immediately reopened and compared through public APIs. Private directories/files use 0700/0600 and no symlinks. No synthetic assistant or successful receipt is written to force persistence.
- Initial Pi round-trip validation compares the actual JSON records written to disk, while separately checking session identity/path; SDK-owned optional undefined fields are omitted by JSON and must not make a valid fresh session fail. Existing-file conflict checks use that same persisted representation, without modifying prior records.
- ACP startup failures use the same fixed safe error envelope as prompt failures, without exposing raw transport/configuration messages. Branch summaries validate their selected entry against the saved Pi session before calling the SDK; an absent target is an explicit not-dispatched input failure, not an unexplained model failure.
- CLI context clear/revert uses an archived Pi branch and a rebuilt public factory under the session lock, never truncates execution history. Pin/recall append explicit user context. Removing arbitrary middle turns is rejected; only the latest complete user turn may be removed. CLI sessions show reads the old transcript; sessions migrate requires explicit goal/artifacts/verification/receipt handoff and never imports the old transcript into Pi.
- Runtime event sequence reserves durable blocks; gaps after a crash are allowed, reused/backward sequence values are not. Tool projections preserve original callId/logicalCallId/toolCallId/executionId and source. Recovery requires a full original binding and native supplier hash match.
- Request budget repair uses only a validated native-unit hint and explicitly not-sent evidence. At most one request projection reduces output and replaces older textual tool bodies with truthful omission markers; system/user messages and the latest tool exchange stay intact. It does not alter saved Pi history or convert bytes to tokens. A fresh quote and increasing request revision remain mandatory; protected minimums that cannot fit fail visibly.
- Long tool loops quote a separate protected completion request: system/developer/user messages, the latest complete tool exchange, no tools, tool_choice=none and max_tokens=512. Host may explicitly start a new completion Turn on its completion stage; completeProtected uses the same Pi session/model bridge with one actual request and automatic compaction/retry disabled. It neither changes the old Turn's scope nor clears unknown execution.
- Local service Hosts may consume durable model receipts through recordModelReceipt and query the original call using inspectModelExecution / ACP model.receipt. Missing usage stays null, never fabricated zero. Receipt replay after recovery preserves call identity/hash and must be idempotent at the Host. Cloud accounting remains the existing Cloud authority.
- CLI watch and the legacy SessionStore read view project saved Pi entries through public SDK conversion. Session selection and Agora auto-intake counters use this read view; no duplicate transcript is written, and legacy append/truncate reject Pi sessions. CLI watch projects saved Pi branches through public SDK conversion. Model pickers refuse busy changes and start a fresh session after a selected profile; they never reopen the old Pi history under a new model. Embedded ACP model/profile selection remains Host-owned and immutable during its authorized task.
- Production export requires committed source and Node 22.23.2, installs only lock-bound production dependencies in an owned staging root, verifies the approved Pi archives offline, and emits an exhaustive resource inventory. The portable packager consumes that export rather than the development tree and refuses target/runtime mismatch or overwriting an existing bundle. Actual export/packaging belongs to the later delivery gate.
- These are product implementation boundaries, not complete-module integration, independent QA, real-model acceptance or a delivered desktop client. TypeScript/build checks alone prove none of those outcomes.

## Boundaries for later implementation

- Pi owns model conversation history and its execution loop. This module may own execution correlation and recovery facts, but must not introduce a second transcript or loop.
- Host identity, permissions, current Turn, and Cloud budget authorization must be checked at their trusted boundaries. A TypeScript shape, ID string, hash, or receipt is not proof of authorization.
- Keep model logicalCallId/callId separate from tool toolCallId/executionId. Keep tool serverId and toolName together when correlating receipts.
- Do not persist raw tool arguments, credentials, Host tokens, or resolvable Secure Input references in execution journals or model history. Persist only the approved hashes, scope data, and safe receipt references.
- Future execution dispatch must follow durable intent recording; future receipt confirmation must follow durable receipt storage. A2 supplies durable journal records but does not wire either ordering guarantee into an executor or Pi.
- Unknown execution results must remain unknown until supported by trustworthy evidence. Cancellation, transport disconnect, or process exit alone does not prove remote execution stopped or that effects did not occur.
- Ordinary confirmed diagnostic failures do not become permanent unfinished obligations. An unrelated success must not erase an unknown effect or an unmet required action.
- This module must not claim Mission acceptance, change Cloud balances, implement Agora internal memory, or silently fall back to the old Agent loop.
